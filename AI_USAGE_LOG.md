# AI Usage Log

A record of how generative AI (Claude, via Claude Code) has been used in this
repository. It exists for transparency with respect to the COMP2850 rule that
AI may be used **only in a supportive, tutoring capacity** for portfolio work.

Entries are appended in date order and never rewritten. Corrections are added
as new entries.

## Entry template

```markdown
### YYYY-MM-DD: <short title>

- **Tool / model:** Claude Code (<model>)
- **Work covered:** <tasks / portfolio weeks>
- **AI did:** <explanations, running builds/tests, reviews, commits, setup...>
- **Student did:** <wrote the code, made the fixes, submitted...>
- **AI-written code:** <none / exactly what and where>
- **Grey areas / notes:** <anything that might fall outside "supportive tutoring">
```

- **Tool / model:** Claude Code in VS Code (Claude Opus 5.5)
- **Work covered:** Portfolio Week 1 (Heron's formula), Tasks 1.3.1, 1.3.2,
  1.4, 2.3, 2.4, plus guidance for Task 3.1.
- **AI did:**
  - Gave an overview of the repo, and of the week 1 brief and which Kotlin Guide
    sections to read (1, 2, 3.1, 3.2, 3.4).
  - Gave a Kotlin crash course: `main(args)`, `val`/`var`, types, `args.size`
    and indexing, `toDouble()`, `if`, arithmetic, `sqrt`, `println` with string
    templates, `"%.5f".format(...)`, `exitProcess(1)`. This ended with a
    step-by-step outline of the program, including Heron's formula written as
    a Kotlin expression.
  - Ran `./kotlin build && python3 check.py` for the portfolio and reported
    the results (first run: 0/8 because the file was unsaved; second run: 5/8).
  - Reviewed the portfolio code after the 5/8 run and named specific fixes:
    the exact required error message, changing `!= 3` to `< 3`, `var` to `val`,
    and stray whitespace. The student made the edits; the final run was 8/8.
  - Committed the student's work for each piece; explained Gradescope upload.
  - Tasks 1.3.1, 1.4: explained the dependency/build configuration and what
    the commands do (no code involved).
  - Task 1.3.2: installed a global `kotlin` command (copied the project's
    official wrapper script to `~/.local/bin/kotlin`); explained the project
    generated by `kotlin init` and its unit tests.
  - Task 2.3: fetched the task's variable definitions from the guide, gave
    hints for predicting types, and explained `UInt` afterwards.
  - Task 2.4: gave guidance; after it was finished, pointed out that the code
    never triggered the `val` reassignment error the task is about.
- **Student did:** Wrote all Kotlin code; made all fixes; ran the programs;
  submitted the portfolio to Gradescope (passed all tests).
- **AI-written code:** None. The AI did not create or edit any `.kt` file.
- **Grey areas / notes:**

    specific line-level fixes to portfolio code is close to the "debug or fix
    your code" use that the brief prohibits. It recommended the student mention
    this to their tutor. The crash-course outline was also quite close to the
    full solution structure.
  - The student asked whether VS Code tab completion counts. The AI explained
    that standard IntelliSense is not generative AI, but Copilot-style inline
    suggestions are, and advised checking which extension was active.
  - The AI's commits from this session carry a `Co-Authored-By: Claude` trailer,
    including the week 1 portfolio commit, even though the AI wrote none of the
    code in them.
